# ICV Admitted Code Assessment — Transaction Boundary

## Customer outcome
Evaluate one proposed code/change admission boundary against a declared target, authority model, evidence requirements, fail-closed predicates, and the existing StegGate/StegCore admissibility design without representing assessment output as production admission authority.

## Intake prerequisites
Identify the customer, accountable owner, exact code/change identity or reproducible source coordinate, intended target/environment, applicable approval/authority assertions, and the evidence the customer is authorized to provide.

## Included deliverables
1. candidate/change identity and target binding;
2. admission-predicate and evidence matrix;
3. bounded StegGate-backed assessment or controlled proof-of-concept where applicable;
4. explicit ALLOW/DENY/REVIEW/FAIL_CLOSED observations produced by the evaluated surface;
5. unresolved authority/runtime gaps;
6. final assessment report and reproduction coordinates where available.

## Exclusions
The service does not create production admission authority, deployment authority, release authority, credentials, trust roots, custody, legal certification, or proof that consequential execution occurred. A test or local ALLOW is not a production execution receipt.

## Commercial terms
Price, schedule, permitted source handling, retention, support, and any implementation work are quoted for the exact scope. No universal numeric price is asserted.

## Acceptance
The assessment is accepted when the agreed candidate/evidence matrix and findings are delivered and reproducible to the extent stated in the scope, with unresolved predicates explicitly retained. Acceptance does not authorize deployment.

## Release boundary
This package is an assessment service. It does not imply that StegGate 0.3.0 or any other underlying software is released. Underlying product release state remains controlled by its canonical repository and release authority.
